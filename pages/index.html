Compose provisions the Loki, Mimir, and Tempo data sources automatically. The repository also includes a Flask dice app, a read-only Grafana MCP service, and Tempo's built-in MCP server.

Built for local development. Grafana allows anonymous Admin access and uses admin / admin credentials. Published ports bind beyond localhost by default. Backends use local container storage without persistent host volumes, so container removal or recreation can lose data. Use a trusted development machine.

01 / Setup

Start the stack

You need Docker Engine or Docker Desktop with Compose v2, Git, and internet access to pull images and build packages. Custom Collector and Tempo builds select Linux amd64 or arm64 packages. Run these commands from the repository root.

git clone https://github.com/ROSMicroPy/GrafanaStack.git
cd GrafanaStack

# Compose expects this shared external network to exist.
docker network inspect observe >/dev/null 2>&1 || docker network create observe
docker compose up -d --build
docker compose ps

Open Grafana at localhost:3000. Sign in with admin / admin if prompted. Services can take a little longer to become ready after their containers start.

Loki (loki:3100) and Mimir (mimir:9009) are internal to the observe Docker network. Grafana reaches them directly.

Stop or rebuild

# Stop without removing containers.
docker compose stop
docker compose start

# Rebuild after changing a configuration copied into an image.
docker compose up -d --build otelcol mimir tempo

# Remove the stack containers; stored telemetry may be lost.
docker compose down

The external observe network remains after down.

02 / Instrument

Send telemetry

Connect your own application

For an application running on your host, configure an OpenTelemetry SDK or auto-instrumentation agent with these environment variables. Environment variables alone do not instrument an application.

export OTEL_SERVICE_NAME=my-service
export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4317
export OTEL_EXPORTER_OTLP_PROTOCOL=grpc
export OTEL_EXPORTER_OTLP_INSECURE=true

For OTLP/HTTP, use http://localhost:4318 with protocol http/protobuf. Signal-specific HTTP endpoints use /v1/traces, /v1/metrics, and /v1/logs. Containers attached to observe should use otelcol instead of localhost.

Try the included dice app

The frontend serves /roll on port 8080 and calls the backend's /roll-dice on port 9090. Both processes run in one container.

The sample testapp/docker-compose.yml currently targets localhost:40317 and the image defaults to Bash. The commands below connect directly to the stack on port 4317 and explicitly start both application processes.
# Run from the repository root after starting the stack.
docker build -t testapp.img ./testapp/testapp
docker run --rm --name grafanastack-dice --network observe \
  -p 127.0.0.1:8080:8080 \
  -e OTEL_EXPORTER_OTLP_ENDPOINT=http://otelcol:4317 \
  -e OTEL_EXPORTER_OTLP_PROTOCOL=grpc \
  -e OTEL_EXPORTER_OTLP_INSECURE=true \
  testapp.img bash -c 'bash run_BE_App.sh & bash run_FE_App.sh & wait -n'

Leave that terminal running. In another terminal, generate requests:

curl http://localhost:8080/roll
for i in $(seq 1 10); do curl http://localhost:8080/roll; echo; done

# Stop the sample when finished.
docker stop grafanastack-dice

The sample mixes Python auto-instrumentation and explicit SDK setup, which can produce provider or duplicate-instrumentation warnings. Launcher service names are dice-fe-server and dice-be-server; the Python code also declares frontend-service and backend-service. Discover the actual service names in Explore. The explicit custom counter uses a console metric exporter, so do not assume that counter is present in Mimir.

03 / Investigate

Explore your data

In Grafana, open Explore, choose a data source, and set the time range to the last 15 minutes. Send a few requests before searching; a fresh stack has no application data.

Logs → Loki

Use the label browser to discover service_name values. For an application named my-service, try:

{service_name="my-service"}

Loki indexes selected resource attributes, including service name, namespace, environment, and node role. Dots in label names become underscores.

Metrics → Mimir

Use the metrics browser to find ingested metrics, then build a PromQL query. Names depend on your SDK and emitted instruments.

This Collector receives OTLP metrics; it does not configure Prometheus scraping. An up query is not a reliable stack health check here.

Traces → Tempo

Use Search to select a service, or start with this TraceQL query:

{ resource.service.name = "my-service" }

Open a trace to inspect spans and timings. Allow a short ingestion delay before retrying a search.

Query with an MCP client

The Grafana MCP service exposes datasource, Prometheus, Loki, and proxied tools with writes disabled. Configure your client's Streamable HTTP connection to http://localhost:8000/mcp. Tempo has its own MCP server enabled on its query frontend. Client setup varies; consult the client's MCP documentation.

For agents working in this repository, AGENTS.md directs log and metric queries to grafana-observability and trace queries to tempo-observability. These are client-side server names, not Docker service names.

Know the configuration

Collector, Mimir, and Tempo configuration files are copied during image builds. Rebuild the corresponding service after edits. Loki's configuration is bind-mounted; restart Loki after editing it. Grafana provisioning is generated by its Compose entrypoint; recreate Grafana after changing that configuration.

The repository pins Grafana to 11.6.0, Loki to 3.3.0, Collector to 0.135.0, and Tempo to 2.10.5. Mimir is installed from the Grafana apt repository without a version pin; the Grafana MCP image uses latest. Rebuilds or pulls can therefore change those components.

05 / Troubleshoot

When something is missing

“Network observe declared as external, but could not be found”
Create it with docker network create observe, then run Compose again.
A container starts, but telemetry does not arrive
Startup ordering does not guarantee readiness. Verify the app's endpoint and protocol, check docker compose ps, and inspect docker compose logs --tail=100 otelcol tempo mimir loki. The Collector's detailed debug exporter can show whether telemetry reached its pipelines.
The sample app cannot connect
The sample Compose file uses port 40317; this stack publishes 4317. Signal-specific endpoint variables override the general endpoint, so update all of them if using that file. The direct Docker command above avoids those defaults.
Grafana shows no results
Check the selected data source, time range, and actual service labels. Verify the application exports the signal you are looking for. Backend storage is not persisted outside the containers.
Tempo service graphs or generated metrics fail
The current metrics generator remote-write URL is http://prometheus:9090/api/v1/write, but this Compose stack has no prometheus service. Configure a valid metrics destination before relying on service graphs or span metrics. This is separate from the Collector's OTLP metrics route to Mimir.
A configuration edit has no effect
Rebuild services whose configuration is copied into an image, or restart Loki for its mounted configuration. Run Compose from the repository root.
A published port is already allocated
Stop the conflicting process or change the host side of the port mapping in Compose. Update application endpoints to match.

06 / Documentation

Publish this guide

This site lives in pages/ and uses plain HTML and CSS. To preview edits locally:

python3 -m http.server 8088 --directory pages

Open localhost:8088. Relative asset links support both this preview and GitHub project Pages.

  1. In GitHub repository settings, open Pages → Build and deployment and select GitHub Actions as the source. This requires repository administration access.
  2. Commit and push to main. The .github/workflows/pages.yml workflow uploads only pages/ and deploys it to the github-pages environment.
  3. Find the published URL in the workflow deployment or repository Pages settings. To republish manually, run Deploy project guide from the Actions tab on main.

Every push to main republishes the checked-in guide. Update the documentation when you change the stack; prose is maintained manually. Feature branches do not deploy. No custom deployment secret is required: the workflow uses GitHub's token and Pages permissions.

For setup details, see GitHub's custom Pages workflow documentation.
